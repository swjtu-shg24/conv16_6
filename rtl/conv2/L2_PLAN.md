# conv2 第二级（L2）添加方案 —— dw3×3 + pw1×1(8→16) + 每 tile 池化

> 目标：在现有 `conv2`（L1：320×240×3 → **160×120×8**，已跑通、整帧 95,903 拍）之后，
> 再接一级 MobileNet 卷积，**尽量复用现有逻辑资源**。
>
> 本文只管**方案**，不动 RTL。看完请先回答 §1 的三个问题，我再开工。

## 0. 结论摘要

| 项 | 结论 |
|---|---|
| 能不能复用 | **能，而且大部分能原样复用**：100 个 PE（`pe_10_10`+`feature_map_12_12`）、`conv_pool_arr`、`conv_cmp4_tree`、`conv_mem_unit`、L2 的 pw 已经是软件流水结构、dw 的窗口预取/9 拍节拍都已就位 |
| 主要改造 | ① `conv_l1` 的通道/输出数位宽写死了（见 §5，**8 处**）② 输入源从 "DDR 带" 换成 "L1 的输出平面" ③ 输出平面要重算片数 |
| 最大风险 | **存储放不下**：如果 L2 输出面写 160×120×16，需要 **240 片** BRAM，加上现有 132 片 = 372 > 256 ✗（见 §6） |

| 预估代价 | L2 约 **~296 拍/tile × 192 tile ≈ 57k 拍**；整帧 L1+L2 ≈ **153k 拍 ≈ 0.77 ms @200 MHz** |

## 1. ★ 先确认三件事（直接影响方案，我不猜）

### Q1：L2 输出面的分辨率到底是哪个？

你说"生成 160×120×16" + "每次输出 tile 进行池化"。这两句在几何上冲突，因为现有 L1 的
tile 是"输入 10×10 → 输出 10×10 → **池化成 5×5** 写回"，写回面**就是池化后的面**：

```
L1:  输入(DDR) 320×240×3  ──tile 10×10──►  10×10×8  ──2×2 max──►  5×5×8  ──►  plane 160×120×8
L2:  输入(plane)160×120×8 ──tile 10×10──►  10×10×16 ──2×2 max──►  5×5×16 ──►  plane 80×60×16
```

所以"每 tile 池化"和"160×120×16 输出面"**不能同时成立**。两种解释：

| 方案 | 含义 | 输出面 | BRAM | 总账 |
|---|---|---|---|---|
| **A（推荐）** | "160×120×16" 指 L2 的**未池化**分辨率；写回面是池化后的 | **80×60×16** | 60 | 12+120+60 = **192/256 ✓** |
| **B** | 输出面就要 160×120×16（不池化，或池化只是内部行为） | **160×120×16** | 240 | 12+120+240 = **372/256 ✗** |

方案 B 放不下，必须再选一个（见 §6.2）：带化输出 / 写回 DDR / 挪走 L1 的平面。

### Q2：激活函数？量化点在哪？

现有 L1 的链路是 `dw → quant36 → pw → quant24 → 2×2 max`（两级量化都带 +128 四舍五入和 clamp）。
MobileNet 标准是 `dw → BN/ReLU6 → pw → BN/ReLU6`。请确认：

- L2 要不要 ReLU/ReLU6？加在哪一级（dw 后 / pw 后 / 池化后）？
- BN 是否已经折进权重（像 L1 那样）？
- 量化沿用 `(x+128)>>>8` 吗？还是换 Q 格式？

> 这一条不定，黄金模型就没法写，tile 也验不了。

### Q3：权重从哪来？

L2 需要 `dw 8×9 = 72` 个 + `pw 16×8 = 128` 个 = **200 个权重**，
加上 L1 的 51 个共 251 个 × 18 bit。现在顶层是 `w_dw[0:26]` / `w_pw[0:23]` 两个端口，
直接扩成 251 个端口不现实（~4.5 kbit 的端口）。建议：

- **推荐**：做一块权重 ROM（`conv_wrom`，BRAM，按 `layer/oc/ic` 寻址），
  从 DDR 或一个窄口预先灌进去（参考 `rtl/mobilenet/mb2/mb2_wrom.v` 的做法）；
- 或者：保持端口，只把位宽扩到 `w_dw[0:71]` / `w_pw[0:127]`（仿真可行，上板占引脚）。

## 3. L2 的数据通路（三处新增 + 一处加宽）

### 3.1 输入源：L1 的输出平面 → 12×12 窗口

L1 面的布局（现有 `conv_plane`）：`unit = (oc*120 + row)*32 + col/5`，一个 unit = 5 B = **同一 oc 同一行的 5 个连续列**。

L2 的 tile(tr,tc)、通道 ch 要的行列 = `[10*tr-1, 10*tr+10] × [10*tc-1, 10*tc+10]`（越界反射，和 L1 一样）。

**关键问题：读一个 12 列的窗口要几次访问？**

| 平面读口宽度 | 一行 12 列要几次 | 每 tile（12 行 × 8 ch） | 每帧（192 tile） |
|---|---|---|---|
| 现状 **1 unit（5 B）** | 3 次 | 288 次 | 55,296 拍 ✗ 比 dw 还慢 |
| **加宽到 4 unit（20 B）** | **1 次** | **96 次** | **18,432 拍** ✓ 能藏进 dw |

> 4 个连续 unit 落在 4 个不同 bank（`unit+i` → `(b+i) mod 6`，i<4<6），
> 所以**一拍能读 4 个 bank 各 1 个 unit** —— 这正是 `conv_band12` 已经在用的机制。
> 建议给 `conv_plane` 加一路 "4 unit 窗口读口"（或者把现有那路单 unit 回读口换成 4 unit，
> tb 回读改成"读 4 个挑 1 个"）。

### 3.2 新增模块 `conv_win_load_plane`

和 `conv_win_load` **结构完全一样**（12 行循环 + 20 B barrel 抽 12 字节 + 左右/上下反射），
只有两点不同：

1. 地址公式从 band 的 `u = slot*(3*CPU) + ch*CPU + k` 换成 plane 的 `unit = (ch*120+row)*32 + col/5`；
2. `bank = unit mod 6`、`addr = unit/6`（现在 L1 面的 addr 是 13 bit，SEG=10，够用）。

> 反射边界从 `IH=240` 变成 `IH=120`、`IW=320` 变成 `IW=160` —— 全部是参数，
> 建议直接把 `conv_win_load` 参数化成 `conv_win_load #(.SRC_BAND/.SRC_PLANE)`，
> 而不是复制一份（复用清单见 §4）。

### 3.3 新增输出面 `conv_plane16`（或给 `conv_plane` 加参数）

| | L1 面 | L2 面（方案 A） |
|---|---|---|
| 尺寸 | 160×120×8 | 80×60×16 |
| 每行 unit | 160 B / 5 = 32 | 80 B / 5 = 16 |
| unit 总数 | 30,720 | 15,360 |
| 结构 | 6 bank × 10 段 × 512 | 6 bank × **5 段** × 512 |
| 片数 | 120 | **60** |
| `unit` | `(oc*120+row)*32 + col5` | `(oc*60+row)*16 + col5` |
| 段号位宽 | `addr[12:9]`（4 bit） | `addr[11:9]`（3 bit） |

`conv_plane` 现在把 `SEG` 写死成 `localparam SEG = 10`，改成 parameter 即可复用。
`conv_mem_unit` 的 `wr_addr[12:9]` 段解码对 SEG=5 也成立（只用低 3 位）。

### 3.4 加宽：写回地址位宽

L1 面的最大 unit = `(7*120+119)*32+31 = 30,719` ⇒ `addr = 5119` ⇒ 13 bit ✓ 现在够。
L2 面最大 unit = `(15*60+59)*16+15 = 15,359` ⇒ `addr = 2559` ⇒ **12 bit** ✓ 更小。

**但如果走方案 B（160×120×16）**：最大 unit = `(15*120+119)*32+31 = 61,439` ⇒ `addr = 10,239`
⇒ 需要 **14 bit**，`conv_mem_unit` 的段解码要从 `[12:9]` 变 `[13:9]`（20 段），
`conv_l1` 的 `p2_wr_addr`/`waddr`/`oaddr` 都要加宽。§5 里按方案 A 列。

## 5. 位宽改造清单（精确到信号，方案 A）

`conv_l1` 现在把通道数写死在**位宽**里，`CIN=8 / COUT=16` 会直接出错（不是"不够用"，
是**比较值被截断成 0**）。必须逐条改：

| # | 位置 | 现在 | 改成 | 不改会怎样 |
|---|---|---|---|---|
| 1 | `reg [1:0] ch` | 2 bit | `[2:0]` | CIN=8 时通道只数到 3 |
| 2 | `output reg [1:0] win_ch` | 2 bit | `[2:0]` | 通道号截断，窗读错通道 |
| 3 | `reg [1:0] pw_cin` | 2 bit | `[2:0]` | pw 的 a 数据选错 `dwc` |
| 4 | `wire pf_vld = (ch < CIN[1:0]-1)` | `CIN[1:0]` | `CIN[2:0]` | **8→`0`**，预取永不触发 |
| 5 | `if (ch == CIN[1:0]-2'd1)`（dw 末通道） | `CIN[1:0]` | `CIN[2:0]` | **8→`0`**，dw 提前结束 |
| 6 | `reg [3:0] oc` + 各处 `oc < COUT[3:0]` / `oc <= COUT[3:0]` / `oc == COUT[3:0]+1`（5 处） | `[3:0]`/`COUT[3:0]` | `[4:0]`/`COUT[4:0]` | **16→`0`**，pw 一拍都不跑 |
| 7 | `output reg [2:0] pool_oc` | 3 bit | `[3:0]` | 池化 oc 号截断 |
| 8 | `dwc [0:CIN-1][0:99]` | 3×100 | 8×100（已是参数，只是变大） | 编译会自动扩，但要确认 `pw_cin` 索引位宽 |
| 9 | `w_dw[0:CIN*9-1]` / `w_pw[0:COUT*CIN-1]` | 27 / 24 | 72 / 128 | 端口爆炸 → 改权重 ROM（Q3） |

**好消息**：`pc`（软件流水组内位置 0..4）与 `CIN` 无关，pw 的**流水结构不用改**，
只是"每组的喂数拍数"从 3 变成 8（见 §8）。

## 6. 存储预算

### 6.1 方案 A（推荐）：L2 面 = 80×60×16

| 缓冲 | 片数 |
|---|---|
| L1 输入带 `conv_band12` | 12 |
| L1 输出面 `conv_plane` | 120 |
| **L2 输出面 `conv_plane16`** | **60** |
| **合计** | **192 / 256 = 75%** ✓ |

余量 64 片，够放权重 ROM（256 个字 × 18 bit ≈ 1 片都不到）和后续扩展。

### 6.2 方案 B（输出面 160×120×16）：240 片，放不下

三条出路（按代价排序）：

| 出路 | 做法 | 代价 |
|---|---|---|
| B1 写回 DDR | `conv_plane16` 不做了，池化结果直接打包写 DDR | 要新增 DDR **写**通路（现在只有读），DDR 带宽 307 KB/帧 ≈ 19.2k 拍 @16 B/拍，可接受 |
| B2 带化 L2 输出 | L2 面只留 16 行（`DEPTH` 取模），下一级边产边用 | 要引入**波前调度**（`mb2/README.md` §6.4 做过一轮、**未完成已回退**，里面有现成的就绪条件公式和踩过的坑） |
| B3 带化 L1 输出 | 把 L1 面从 120 片缩成 16 行带（16 片），腾出 104 片给 L2 面 | L1 也要波前调度，改动面更大 |

> 我倾向 **A**：既对称、又不用碰调度，还能保住"BRAM 只占 75%"这个余量。

## 6.3 ★ 原地复用同一块 plane 的地址映射（**已确认走这条路**）

你选了 B（写回同一块物理 RAM）。我把映射推了一遍，发现一个**非常干净**的性质：

> **L1 面的一行 = 8 ch × 32 unit = 256 unit；L2 输出的一行 = 16 oc × 16 unit = 256 unit。两者正好相等！**

所以只要把 **L1 的行号直接当成 L2 的行号用**，一块 RAM 就同时装得下两级：

```
L2 输出 (oc2, r2, k2)  →  plane unit = ((oc2>>1)*120 + r2)*32 + (oc2&1)*16 + k2
                                       └──── 借用 L1 的 ch = oc2>>1 ───┘  └ 前半/后半行 ┘
```

即：**L1 通道 c 的那一行 32 个 unit，前 16 个给 L2 的 oc2=2c，后 16 个给 oc2=2c+1**。
L2 只用 plane 的**行 0..59**（15,360 unit = 一半），**L1 的行 60..119 永远不动**。

### 为什么不会踩到"还没读的 L1 数据"

| 事件 | 时机 |
|---|---|
| L1 的**行 R** 最后一次被 L2 读 | L2 的 tile 行 `floor((R+1)/10)` |
| L1 的**行 R** 被 L2 输出行 R 覆写 | L2 的 tile 行 `floor(R/5) + 1`（见下"延后一行写"） |

`floor(R/5)+1 > floor((R+1)/10)` 对一切 R 成立 ⇒ 覆写永远发生在最后一次读之后 ✓

**但必须"延后一个 tile 行"写**：tile 行 tr 自己就要读 L1 的行 `10tr-1..10tr+10`，
其中包含输出行 `5tr..5tr+4`（就地写就会自踩）。所以：

- tile 行 tr 的池化结果，**在 tile 行 tr+1 期间写出去**（写 L1 行 `5tr..5tr+4`，
  而 tr+1 读的是行 `10tr+9..10tr+20`，不重叠 ✓）；
- 最后一个 tile 行（tr=11）的结果用一个 **flush 收尾**；
- 所需缓冲：**一个 tile 的池化结果 = 5 行 × 16 oc × 1 unit = 80 unit × 40 bit = 3.2 kbit**
  → 寄存器就够，不用 BRAM。

### 写回地址递推（相对 L1 只改"每 oc 的增量"）

```
tile 基底 = tile_r*160 + tile_c      ← 和 L1 **完全相同**（这点很关键）
行间     : unit += 32                ← 和 L1 **完全相同**（bank+2 / addr+5+进位）
oc 间    : 偶数 oc2 → unit += 16     （bank+4 / addr+2+进位）
           奇数 oc2 → unit += 3824   （= 3840-16；bank+2 / addr+637+进位）
```

所以 `conv_l1` 的写回地址逻辑只需在"oc 边界"加一个 **2 选 1 的增量**，
其余（行递推、基底、5 拍写一行）**一字不改**。

**BRAM 总账不变：band 12 + plane 120 = 132/256 ✓**

## 6.4 ★ 新增阻塞点：DSP 不够 + pw 相位按 CIN=3 写死

### (a) DSP

现在 **100 个 DSP**。若给 L2 再例化一套 `conv_l1` ⇒ **200 DSP**，Ti60 大概率没有这么多
⇒ **必须 L1/L2 共用同一套 100 PE**（时分复用），`conv_l1` 改造成"可配层的卷积引擎"：
`CIN/COUT` 变运行时配置、权重走 ROM、窗口源在 `conv_win_load`(band) 与
`conv_win_load_plane`(L1 面) 之间做顶层 mux。

### (b) ★ pw 的软件流水是**按 CIN=3 / 周期 5 写死**的（这是真正的工作量所在）

现在的 pw：`pc` 数 0..4（周期 `P=5`），所有动作的拍号都是**字面量**：

```verilog
if (pc <= 5'd2)                 // 喂 a：CIN=3 拍
if (pc >= 5'd1 && pc <= 5'd3)   // 喂 b
if (pc == 5'd2)                 // 量化 oc-1
if (pc == 5'd3 || pc == 5'd4)   // 池化 en 两拍
if (pc == 5'd4)                 // 装写回基底
```

CIN=8 时"一组"要喂 8 拍，周期必须 `P ≥ CIN`（`feature_map` 被占住到最后一个乘积），
所以 **P=8**，而"格" = `CIN+12 = 20` ⇒ **同一拍上有 3 个 oc 在飞**，
且各动作落在"组"里的位置随 CIN 变。

| 动作 | 现在（CIN=3, P=5） | 通用式（s = oc 自己的格内拍号） |
|---|---|---|
| 喂 a（`wdata_en`/`pw_cin`） | `pc <= 2` | `s = 0..CIN-1` |
| 喂 b（`pe_lb`） | `pc` 1..3 | `s = 1..CIN` |
| 累加 / 量化 | `pc==2` 量化 | `s = CIN+4` 量化 |
| 池化 en | `pc==3,4` | `s = CIN+5, CIN+6` |
| 写回 | 5 拍 | `s = CIN+7 .. CIN+11` |
| 周期 | `P = 5`（写口限） | **`P = max(CIN, 5)`** |

**建议实现**：把 (组 `oc`, 组内位置 `pc`) 的写法换成 **"全局拍号 `pn` + 每个 oc 自己的 `s = pn - o*P`"**，
否则 (组, m) 的偏移随 CIN 变、很难维护。

> **硬约束**：L1 那条流水必须**一拍不差** —— 它被 `tb_board` 的校验和 `eb131b12a5` 钉死
> （BN 插入前是 `c2eaf2eaaf`）。参数化 CIN 之后，L1 仍必须落回 `P=8`、`pc` 数 0..7，
> **校验和不能变**。
>
> ⚠️ **本节已过期（BatchNorm2d 插入后重写）**：L1 现在的"组"是 **8 拍**（`P=8`，`pc=0..7`），
> 而且**每个 oc 还要多占 1 个 fm 载入拍给 BN**（m=0 载 `qq`）。所以通用式要改成：
>
> | 动作 | 现在（CIN=3 + BN, P=8） | 通用式（s = oc 自己的格内拍号） |
> |---|---|---|
> | 载 BN 的 a（`qq`） | `m=0` | `s = 0` |
> | 喂 a（`wdata_en`/`pw_cin`） | `m=0..2`（载入落在 m=1,2,3） | `s = 1..CIN` |
> | 喂 b（`pe_lb`） | `m=0` 给 BN 的 `bn_a`；`m=1..3` 给 `w`（落在 m=2,3,4） | BN 的 b 在 `s=1`；`w` 在 `s = 2..CIN+1` |
> | BN 的 `C`（`c_bn`） | `m=3` | `s = CIN+2` |
> | 抓 `bnq` | `m=4` | `s = CIN+3` |
> | 抓 `qq`（量化） | `m=7` | `s = CIN+6` |
> | 池化 en | `m=5,6` | `s = CIN+4, CIN+5` |
> | 写回 5 行 | `m=0..4` | `s = CIN+8 .. CIN+12`（跨到"下一组"的拍号） |
> | 周期 | `P = 8` | **`P = max(CIN+5, 8)`** —— CIN=3 时正好 8；CIN=8 时 **P=13** |
>
> 全帧代价（CIN=8 的 L2）：`S_PW = (COUT+2)*P`。L1 现在是 `10*8 = 80`；
> L2（COUT=16）会是 `18*13 = 234` 拍/tile —— 先按这个估，跑通再优化。
> **`P` 必须从 `CIN` 推出来**（不要再写字面量），否则 L1 和 L2 会互相踩。

## 7. 调度方案

### 7.1 第一版（简单、先跑通）：L1 整帧跑完 → L2 整帧跑

`conv_sched` 现在只调度 L1（`NTILE_R×NTILE_C` 个 tile，`done` 后停）。
加一层"阶段"即可：

```
S_L1: 现有逻辑，done_L1 后 → S_L2
S_L2: tile 网格 12×16 = 192 个（160×120 / 10），tile_r/tile_c 复用同一套计数器
      窗口就绪条件：L1 面已全部写完（就是 done_L1）
最终 done = done_L1 & done_L2
```

- **优点**：几乎不动现有调度；L2 的窗口源（L1 面）在 L1 结束时已经完整，不需要任何"就绪握手"。
- **缺点**：L1 与 L2 之间有一段"L1 尾巴"没法重叠（L2 的 tile(0,0) 其实只要 L1 面的前 11 行就够）。

### 7.2 第二版（可选的性能优化）：按 tile 行流水

L2 的 tile 行 `tr` 只要 L1 面的 `10*tr-1 .. 10*tr+10` 行。所以 L1 做完前 11 行就能起 L2 的
tile 行 0。就绪条件（照 mb2 §6.4 的公式，注意**末行必须截断**，否则死等）：

```
L2 tile 行 r 就绪  <=>  L1 已写完的 pool 行数 >= min(10*r + 11, 120)
```

收益：L2 的 192 tile 里大部分能藏进 L1 的尾巴。**建议放到第二版**，第一版先不碰，
避免把已经全绿的调度改坏。

## 8. 性能估算（按现有结构推）

### 8.1 L2 单 tile

| 相位 | 算法 | 拍数 |
|---|---|---|
| `S_DW` | `CIN × 14`（8 通道，抓数拍仍是 `c=13`，窗口预取照用） | **112** |
| `S_PW` | 软件流水，周期 `P = max(CIN+3, 写口 5) = 11`；`(COUT-1)*P + 格19` | **184** |
| `S_WREQ/S_WWAIT/S_DONE` | 窗读藏在 dw 里（96 次 < 112） | ~2 |
| **合计** | | **≈ 298 拍/tile** |

### 8.2 整帧

```
L1 :  95,903 拍（已实测）
L2 :  192 tile × 298 ≈ 57,200 拍
合计 ≈ 153,100 拍 ≈ 0.77 ms @200 MHz
```

对比参考：`mb2`（160×160 版）整条 3 级链 54,990 拍，其中 L2（16→32、16 tile）占大头 —— 
说明这个数量级是合理的。

### 8.3 如果想更快

- L2 的 `S_PW` 是新的瓶颈（184/298 = 62%）：把 pw 的软件流水周期从 11 压到 8 需要
  **双缓冲 `feature_map`**（一份喂 a、一份算），代价是 144×18 = 2592 个触发器；
- 或者把 L2 的 `S_DW` 用已经验证过的 **9 拍节拍**（`tb_pe_dw_stream` 的 CAD=9）：
  112 → 72，省 40 拍/tile（≈7,700 拍/帧）。

**已知的坑（提前记下，实施时会撞）**：

1. `CIN/COUT` 的比较值**会被位宽截断成 0**，不是"不够用"（§5）。
2. 预取/末通道判断的 `CIN[1:0]`、`COUT[3:0]` 全都要跟着加宽，**漏一处就静默少算**。
3. L2 的 dw 窗口源是**平面**，地址公式和 band 完全不同；反射的边界也从 320/240 变成 160/120。
4. `pw_cin` 从 2 bit 变 3 bit 后，`dwc[pw_cin]` 的索引位宽要跟着改（`↑8` 位宽不匹配会出 Z）。
5. L2 面的段数变成 5 之后，`conv_plane` 里 `rseg_d == i` 的段选比较位宽要跟着调。
6. 若走方案 B，`conv_mem_unit` 的段解码要从 `addr[12:9]` 变 `addr[13:9]`（20 段），
   牵动 `conv_plane`、`conv_l1` 的写回地址递推（`+640` 那套要重算：现在 `3840 % 6 == 0`，
   16 通道时 `oc` 步进仍是 3840 ⇒ 递推公式不变，但位宽要加）。

# conv 内存方案 V4（输入已是池化后的 320×240×3）

> 前提（按你的说明重置）：
> ① 送进来的数据**已经是池化后的 320×240×3（8bit/ch）**，整帧可用；输入池化模块**不在本设计内**。
> ② 积木 = `bram_10kb`（SDP, 512 字 × 20 bit = **1,280 B/片，100%**，已实测 `bram_mapping_size = 1`）。
> ③ 访问单元 unit = 40 bit = **5 B**（2 片同址并联）；bank = unit mod N，一次访问 5N 字节。
> ④ PE 全流水线：每 tile 拍数 = `CIN×9 + CIN×COUT`。
>
> 本文取代 `MEM_REUSE_PLAN.md` 里所有与"输入池化/640×480"相关的部分。

---

## 1. 总池：132 片 = 51.6%

| 区域 | 数据量 | unit 数 | bank | 结构 | 片数 | 读/写带宽 |
|---|---|---|---|---|---|---|
| `B` band12（12 行 × 320px × 3ch） | 11,520 B | 2,304 | 3 | 每 bank 768 unit → 2 段 × 2 片 = 4 | **12** | 15 / 15 B/拍 |
| `C` plane（P2 / P4 / P5 共用） | 153,600 B | 30,720 | 6 | 每 bank 5,120 unit = 10 段 × 512 → 20 片 | **120** | 30 / 30 B/拍 |
| **合计** | 165 KB | | | | **132 / 256 = 51.6%** | 余 124 片 = 155 KB |

- **不再有输入行缓存**（raw 行与池化都不进本设计）。
- `B` 取 3 bank 的理由不是速率而是**粒度**：窗口一次要 10~12 个连续字节，3 bank 一次访问 15 B，任意 5B 对齐都一次装下（2 bank 只有 10 B，跨 unit 时要点 2~3 次，36 拍会涨到 72~108 拍，超过 51 拍/tile）。

## 2. 带宽账（按 51 拍/tile 重算）

| 通路 | 需求 | 供给 | 判定 |
|---|---|---|---|
| 输入 → `B` 写 | 一帧 230,400 B；L1 每 10 行池化面（1,632 拍）要 9,600 B → **5.9 B/拍** | 15 B/拍 | ✅ 2.5× 余量 |
| `B` 读（L1 窗口） | 3ch × 12 行 × 15 B = 540 B/tile ÷ 51 = 10.6 B/拍（有效 360 B = 7.1） | 15 B/拍 | ✅ 1 次访问/行 |
| `C` 写 | L1 200 B/tile = 3.9；L2 400 B/200 拍 = 2.0；L3 800 B/656 拍 = 1.2 B/拍 | 30 B/拍 | ✅ 极大富余 |
| `C` 读 | L2 1,152 B/200 拍 = 5.8；L3 1,920 B/656 拍 = 2.9 B/拍 | 30 B/拍 | ✅ 极大富余 |

**输入不再是关键路径**：整帧输入 = 230,400 B ÷ 16 B/beat = **14,400 拍**，而 L1 = **39,168 拍** → 输入比计算快 2.7 倍，靠 band12 的环+`rows_free` 握手自然节流即可，不需要 DDR 分块节流。

## 3. 时间预算（PE 全流水线）

| 级 | `CIN×9 + CIN×COUT` | 拍/tile | tile | 拍 |
|---|---|---|---|---|
| L1 (3→8) | 27 + 24 | **51** | 768 | 39,168 |
| L2 (8→16) | 72 + 128 | **200** | 192 | 38,400 |
| L3 (16→32) | 144 + 512 | **656** | 48 | 31,488 |
| 每 tile 收尾（量化/池化/写回）合计 | | | | ≈ 16,000 |
| **总计** | | | | **≈ 125,000 拍 ≈ 0.63 ms @200MHz** |

## 4. 相位与内存身份（复用主线不变）

| 相位 | 活跃 | 片数 | 说明 |
|---|---|---|---|
| P0 | `B` + `C`=P2 | 132 | 输入写 `B`、L1 读 `B` 写 P2（`B` 12 行环，每 tile 行推进 10 行） |
| P1 | `C`：P2 读 / P4 写 | 120 | L1 完成且 `p2_full` 才启动；`B` 释放 |
| P2 | `C`：P4 读 / P5 写 | 120 | L2 完成才启动 |

**原地覆盖规则**（两视图行字节数相同是根本原因）：

```
P2 行 = 160px × 8ch  = 1280 B = 256 unit
P4 行 =  80px × 16ch = 1280 B = 256 unit   → P4 行 r 写 P2 行 r 的地址
P5 行 =  80px × 32ch = 2560 B = 512 unit   → P5 行 r 写 P4 行 2r 的地址
安全：产生 P4 行 r 时已消费 P2 到行 2r+2；产生 P5 行 r 时已消费 P4 到行 2r+2 → 写指针落后 ≥2 行
纪律：wr_row ≤ rd_row − 2 断言；每 tile 先装完窗口再写回；跨帧清指针
```

## 5. 地址映射（unit = 字节地址 ÷ 5）

```
B band12 : unit = slot*192 + ch*64 + u     slot = row mod 12, ch 0..2, u 0..63   bank = unit mod 3
C P2     : unit = (ch*120 + row)*32 + u    (160 B/行 = 32 unit)                  bank = unit mod 6
C P4     : unit = (ch* 60 + row)*16 + u    ( 80 B/行 = 16 unit)
C P5     : unit = (ch* 60 + row)*32 + u    (160 B/行 = 32 unit)
基址(unit)：B = 0 .. 2303      C = 2304 .. 33023（C 占 30,720 unit）
```

## 6. 握手信号

| 信号 | 产生 | 含义 |
|---|---|---|
| `in_row_vld` | 输入侧 | 一行 320×3 B（20 beat）写完 `B` 的某个 slot |
| `rows_free` | L1 | 上一 tile 行已消费完 12 行中的前 10 行 → 允许生产者推进环 |
| `p2_full` | L1 | P2 全图写完 → 允许 L2 启动 |
| `p4_full` | L2 | P4 全图写完 → 允许 L3 启动 |
| `frame_done` | L3 | 输出完成 → `done`，`phase` 回 P0、清指针 |

## 7. RTL 清单

| 模块 | 职责 |
|---|---|
| `conv_cmp4_tree.v` | 4 输入比较树（两级流水打拍） |
| `conv_pool_arr.v` | ROWS×COLS 参数化阵列（写回池化用 5×5；本设计不含输入池化） |
| `efx_ram20.v` | `bram_10kb` 封装（参数化段数；40 bit unit = 2 片同址并联） |
| `conv_band12.v` | 12 行带（3 bank / 12 片）、slot 环、`rows_free` 握手 |
| `conv_in_dma.v` | 只做**搬数**：320×240×3 一帧从 DDR 写进 `B`（按行 320 B = 20 beat），无池化 |
| `conv_l1/l2/l3.v` | 窗口装配（12×12 寄存器，反射边界）+ 拍级调度（51/200/656） |
| `conv_mem_pool.v` | 唯一做"字节 → unit → bank → 片"解码的地方 |
| TB / `filelist.f` / `sim_conv.do` / `run.bat` | ModelSim 一键，逐字节对软件黄金模型 |

## 8. 验证要点

1. 片数 132（综合报告 RAMs 列 + `efx_ram20` 例化计数）。
2. `B` 的 12 行环：`slot = row mod 12`、推进 10 行、`rows_free` 不越界（断言）。
3. 原地复用：P2/P4/P5 三视图同一字节地址的三角校验（写 P4 行 r 后读回 P2 行 r 地址，确认只改到预期行）。
4. 带宽：统计每相位读/写拍数 ≤ 供给（每 tile 窗口读 ≤ 36 拍、写回 ≤ 8 拍）。
5. 端到端：逐字节比对软件参考模型（P2 160×120×8、P4 80×60×16、P5 80×60×32）。

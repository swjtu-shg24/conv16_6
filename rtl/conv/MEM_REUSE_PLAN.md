# conv 内存复用详细计划（V3，基于已验证的 `bram_10kb` SDP 积木）

> 实测前提（已确认）：`ip/bram_10kb` = **SDP_RAM，512 字 × 20 bit = 10,240 bit = 1,280 B，`bram_mapping_size = 1`**
> → **一片 = 1,280 B，位效率 100%**。GUI 综合已跑到 bitstream（`u_ip0:bram_10kb` 报 1 片）。

---

## 1. 积木与访问单元

| 项 | 定义 |
|---|---|
| 物理片 | 1 片 = 512 × 20 bit = 1,280 B（1 写口 A + 1 读口 B） |
| 访问单元 | **unit = 40 bit = 5 B = 2 片同址并联**（一个字装 5 字节） |
| 为什么 5 B | 池化块宽 = 5（10×10 → 5×5），写回"每行 5 字节" = 正好 1 unit；且 **1280 B/行 = 256 unit、2560 B/行 = 512 unit 都整除** → 所有行天然按 unit 对齐 |
| 单元内字节映射 | word_lo[19:0] = {b0,b1,b2[3:0]}；word_hi[19:0] = {b2[7:4],b3,b4}（整 unit 写，不需要读改写） |
| 每 bank | 深的 40 bit 存储器 = 深度/512 段 × 2 片 |

## 2. 总池：134 片 = 52.3%（166 KB 数据）

| 区域 | 数据量 | unit 数 | bank | 结构 | 片数 | 带宽 |
|---|---|---|---|---|---|---|
| `A` 输入行缓存 | 1,280 B | 256 | 1 | 1 段 × 2 片 | **2** | 5 B/拍 |
| `B` band12（12 行 × 320px × 3ch） | 11,520 B | 2,304 | 2 | 各 1,152 unit → 3 段 × 2 片 = 6 | **12** | 10 B/拍 |
| `C` plane（160×120×8 / 80×60×16 / 80×60×32） | 153,600 B | 30,720 | 6 | 各 5,120 unit = **10 段 × 512** → 10 段 × 2 片 = 20/ bank | **120** | 15 B/拍 |
| **合计** | | | | | **134 / 256 = 52.3%** | 余 122 片 = 156 KB |

> `C` 用 **6 bank × 10 段 × 2 片 = 120 片**：30,720 unit / 6 bank = 5,120 unit/bank = 10 × 512 **整除** → 100% 无浪费。
> `B` 2,304 unit 拆 2 bank 各 1,152 → 3 段（1,536）→ 75%；若只要 5 B/拍可改 1 bank × 5 段 = 10 片（90%）。
> unit 地址 → `bank = unit mod 6`（2 的幂无关，但 6 的取模可用 `unit - 6*floor(unit/6)` 或直接把 unit[2:0] 做 bank 选择表；建议 **6 bank 用 unit%6 的 3 位比较**，只做加法/比较，不做除法）。

## 3. 相位划分：同一批片在不同相位改身份

| 相位 | 活跃区域 | 片数 | 进入条件 | 退出条件 |
|---|---|---|---|---|
| **P0 输入+L1 流水** | A(2) + B(12) + C=**P2**(120) | **134** | `start` | L1 最后一个 tile 写完 |
| **P1 L2** | C=**P2 读 / P4 写**（120） | 120 | L1 完成（P2 全图就绪） | L2 最后一个 tile 写完 |
| **P2 L3** | C=**P4 读 / P5 写**（120） | 120 | L2 完成 | L3 完成 → `done` |

**关键复用点：**

1. **`C` 三次改身份，零额外片**：`P2(160×120×8)` → `P4(80×60×16)` → `P5(80×60×32)`，三者共用同一 120 片。
2. **行缓存 A 与 band12 B 只在 P0 活跃**，P1/P2 释放（12+2 片闲置，不进峰值）。
3. **相位严格串行**（P1 只在 P2 全图写完后开始）→ 复用不需要复杂的并发仲裁，只靠 `phase` 寄存器切换基址/边界。

## 4. 原地覆盖规则与安全证明

| 复用 | 地址规则 | 安全证明 |
|---|---|---|
| `P2 → P4` | `P4` 行 r（80px×16ch = **1280 B** = 256 unit）写到 `P2` 行 r 的地址 | 产生 `P4` 行 r 时已消费 `P2` 到行 `2r+2`（P4 行 r ← P3 行 2r/2r+1 ← P2 行 2r-1..2r+2）→ 写指针落后读指针 ≥2 行 |
| `P4 → P5` | `P5` 行 r（80px×32ch = **2560 B** = 512 unit）写到 `P4` 行 2r 的地址 | 产生 `P5` 行 r 时已消费 `P4` 到行 `2r+2` → 写指针落后 ≥2 行 |

**两个视图行字节数完全相同**是复用成立的根本原因：`160×8 = 80×16 = 1280 B/行`；`80×32 = 2560 B/行 = 2 行 P4`。

**纪律（必须写进 RTL）**：
- `wr_row ≤ rd_row − 2` 断言（`rd_row` = 当前正在读的输入行）；
- 每 tile 的写回必须发生在"该 tile 的输入窗口已全部装入寄存器"之后（读后写，不读改写）；
- 相位切换时清指针，不跨帧复用残留。

## 5. 相位内的环与握手（P0）

| 缓冲 | 环规则 | 握手 |
|---|---|---|
| `A` 行缓存 | 偶行（2r）整行写入，奇行（2r+1）到达时读回 | `A_full`（偶行写完）/ `A_done`（奇行读完） |
| `B` band12 | 12 行环，`slot = 行号 mod 12`，每算完一个 tile 行**推进 10 行**（序列 0,10,8,6,4,2,0…） | 生产者写 10 新行前必须收到 `rows_free`（消费者已消费上一 tile 的 12 行中的前 10 行） |
| `C` P2 | 由 L1 写回（每 tile 5×5×8 = 200 B = 40 unit），每行 160 B | L2 只在 P2 全图写完（`p2_full`）后启动 |

**速率核对**：一个 tile 行（10 行池化面 = 32 tile）消费 32 × 120 = 3,840 拍；生产 10 个池化行需 20 个原始行 = 1,600 拍（DDR 节流后 8 px→5 B/拍 约 3,200 拍）→ 生产者仍不慢于消费者，`B` 的 12 行环够用。

## 6. 地址映射表（unit 地址 = 字节地址/5）

```
A 行缓存 : unit = 0 .. 255            bank = unit % 1（单 bank）      → base 0
B band12 : unit = slot*192 + ch*64 + u   (行 960 B = 192 unit；通道 320 B = 64 unit)
           slot = row mod 12；bank = unit % 2
C plane  : P2 视图  unit = (ch*120 + row)*32 + u    (行 160 B = 32 unit，每行 32 unit)
           P4 视图  unit = (ch* 60 + row)*16 + u    (行  80 B = 16 unit)
           P5 视图  unit = (ch* 60 + row)*32 + u    (行 160 B = 32 unit)
           bank = unit % 6
基址：A=0, B=256, C=2816（unit 为单位；C 占 2816..33535）
```

## 7. RTL 模块与指针归属

| 模块 | 拥有的指针/状态 |
|---|---|
| `conv_in_dma` | `row`（源行 0..479）、`A_wr_cnt`、`beat_cnt`、`ddr_len=4` 分块请求 |
| `conv_band12` | `slot_wr`/`slot_rd`（mod 12）、`rows_free` 握手、`phase` |
| `conv_pool_arr` | 无存储指针（纯组合+两级流水） |
| `conv_l1` | `tile_r`/`tile_c`、`P2_wr_row`、`p2_full` |
| `conv_l2` | `P2_rd_row`、`P4_wr_row`、`phase=P1` |
| `conv_l3` | `P4_rd_row`、`P5_wr_row`、`phase=P2` |
| `conv_mem_pool` | `efx_ram20` × 134 例化 + unit/bank 地址解码（唯一的地方做字节→unit→片映射） |

## 8. 边界与异常

1. **帧首**：`A` 未满时不启动池化；`B` 未积累 12 行时不启动 L1（`E_PRE` 等待）。
2. **帧尾**：最后 2 个池化行不足 12 行环 → 用 `slot` 计数上限而非取模判定结束；`P2` 最后一行写完才置 `p2_full`。
3. **反射边界**：L1/L2/L3 的 12×12 窗口在图像边缘按 `-1→1、N→N-2` 反射（沿用 `mb2_lb` 的做法），反射发生在**窗口装配阶段**，不额外占存储。
4. **跨帧**：`phase` 回 P0，指针清零；不复用上一帧残留（不依赖清零的存储视为无效）。

## 9. 验证方法

| 检查 | 手段 |
|---|---|
| 片数 134 | GUI/命令行综合报告 RAMs 列 + `efx_ram20` 例化计数 |
| 原地复用正确性 | TB 里对 `P2/P4/P5` 三视图做**同一字节地址的三角校验**（写 P4 行 r 后立刻读回 P2 行 r 地址，确认改写的是预期行） |
| 读写纪律 | `wr_row ≤ rd_row-2` 断言 + 每帧结束时对比黄金模型（软件 Python 参考模型逐字节） |
| 带宽 | 统计每 phase 的读/写拍数（`< tile 拍数` 即通过） |
| 时序 | 200 MHz 下每 bank 1 读 + 1 写/拍；窗口装配用寄存器分拍（1152 FF/通道） |

## 10. 与旧方案的差异（一句话）

旧 `mb2_cache` 用 16 个 bank × `bram_1KB`（8 bit 宽、80% 效率、160 片、只有 16 行带）；V3 用 **1,280 B/片 的 20 bit SDP 积木** + **相位串行的原地复用**，同样功能只要 **134 片**，而且 `plane` 是真正的全图缓存（不是 16 行带），窗口可以在图上任意滑动。

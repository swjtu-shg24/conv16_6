# conv 前端详细方案：存储结构 / 计算过程 / 资源消耗 / 可行性

> 网络：`640x480 RGB565` →2x2池化→ `320x240x3` →dw3x3+pw1x1→ `320x240x8` →池化融合→ `160x120x8`
> →dw3x3+pw1x1→ `160x120x16` →池化融合→ `80x60x16` →（可选第三级）`80x60x32`
> 数据 8bit，一个 PE 拍两次 8bit MAC。器件 Ti60F225。
> 配套：`BRAM_PLAN.md`（存储评估快照）；本文是完整方案。
>
> ⚠️ **修正（2026-09-19，实测）**：本文 §3.1/§3.2/§3.3 关于"128 bit 宽字 = 1 片 = 1280 B"的结论**已被 Efinity 实测推翻**
> （`80x128` 实测 7 片、`10240x120` 实测 240 片）。存储结构以 **`BRAM_VERIFY.md`（V2）** 为准：
> 只用 `1024x8` 字节宽 bank，`band12` 16 片 + `plane` 160 片 = **176/256 片**，输入行缓存取消（DDR 双读）。
> §4（计算过程）、§4.7（DUAL 模式）、§5.1（FF 爆表分析）、§6（实施）不受影响。

## 1. 方案总览

```
        DDR (128bit/beat = 8px RGB565)
          │  行 2r  → raw_line(1 片)
          │  行 2r+1 ──┐
          │            ├─ 2x2 max4 (4 棵/拍) ─ 12B/拍 ─→ band12 (9 片, 12 行 x 320px x 3ch)
          └── raw_line ┘                                        │
                                                   窗口装载(12x12/ch) │
                                                                ▼
                       ┌──────────── L1 引擎 (10x10 PE 阵列) ────────────┐
                       │ 复用卷积 dw3x3(3ch) → pw1x1(3→8) → 量化        │
                       │ → 池化树阵列 5x5 (25 棵 max4) → 5x5x8          │
                       └───────────────────┬────────────────────────────┘
                                           │ 200 B/tile 字节使能写
                                           ▼
                              plane (120 片, 160x120x8)
                                           │ 窗口装载 + 原地写回
                                           ▼
                       ┌──────────── L2 引擎 ────────────────────────────┐
                       │ dw3x3(8ch) → pw1x1(8→16) → 池化 → 5x5x16       │
                       └───────────────────┬────────────────────────────┘
                                           │ 400 B/tile
                                           ▼
                          plane 内 80x60x16（与 160x120x8 同址，见 §3.5）
```

|---|---|---|

## 2. 器件与资源基线

| 资源 | Ti60F225 | 上一版 mb2_full（`outflow/conv10_10.res.csv`） |
|---|---|---|
| 10K RAM（10 Kbit/片） | **256 片 = 320 KB** | 160 片（62.5%） |
| DSP48（19x18，DUAL 可做 11x10+8x8） | **160** | 100（62.5%） |
| XLR / LUT4 | **60,800** | 57,185（**94%**） |
| FF | ≈ 60,800（每 XLR 1 个） | **139,847（超 2.3 倍）** |

**重要发现（决定了新方案的走向）**：上一版 `mb2_top` 把中间结果全放在 FF 里——
`reg signed [17:0] dwc[0:31][0:99]` = 57,600 FF、`reg [7:0] blk[0:63][0:99]` = 51,200 FF、`pacc[0:99]` 48bit = 4,800 FF，
三者相加 113,600 FF，**FF 用量是器件容量的 2.3 倍，物理上放不下**。
→ 新方案必须：**中间平面进 BRAM + 按 oc 算完立即池化写回（不攒 blk[64][100]）+ 8bit 累加**。这是本方案最主要的设计约束。

## 3. 存储器结构

### 3.1 片型选择：一片 = 80 字 x 128 bit = 1280 B（100% 利用）

一片 10K RAM = 10,240 bit。存 8bit 数据时各模式利用率：

| 模式 | 每片 | 利用率 |
|---|---|---|
| 1024 x 10（`bram_1KB` 用 1024x8，1 片只吃 8 Kbit） | 1024 B | **80%（旧方案亏 20%）** |
| 512 x 20 | 1024 B | 80% |
| 256 x 40 | 1280 B | 100% |
| **80 x 128（选用）** | **1280 B** | **100%** |

- **一个字 = 16 个连续列**（同一通道同一行），一次访问就是 16 B/拍；**一片就能顶旧方案 16 个 bank**，且不浪费容量。
- 旧方案 `mb2_cache.v` 用 `bank = 列号 mod 16` + 16 片 `bram_1KB`：功能等价（都是"同一 (ch,row) 上连续 16 列"），但至少吃 16 片/8 Kbit 有效容量。
- 端口用 **SDP（A=写，B=读）**：生产者/消费者天然分开；平面的"边读边写（原地覆盖）"也只要 1R+1W。
- IP 必须开 **字节使能**（`BYTEENA_ENABLE/BYTEENB_ENABLE=1`）：池化写回一卷只有 5 B/行/通道。

### 3.2 存储清单

| 名 | 形状（V2 实测修正） | 片数 | 容量 | 作用 |
|---|---|---|---|---|
| `conv_raw_line` | 取消：DDR 偶/奇行交错读 + 寄存器 FIFO | **0** | — | 原始偶数行不进 BRAM |
| `conv_band12` | **16 bank x `1024x8`**（每 bank 720 B） | **16** | 11,520 B | 12 行 x 320 px x 3ch 池化面，bank = 地址低 4 位 |
| `conv_plane` | **16 bank x 10 片**（每 bank 9,600 B） | **160** | 153,600 B | `160x120x8` 全图，兼 `80x60x16`/`80x60x32`（原地） |
| 小计 | | **176 / 256 = 68.8%** | 165 KB | 余 80 片 |

### 3.3 地址映射（位域）

```
raw_line : addr[6:0] = beat 号 (0..79)                        1 字 = 8 px RGB565
           写：DDR beat 直写；读：做 2x2 池化时同址 1 拍延迟读出

band12   : 行 = 3 个通道子行，每子行 320 B = 20 字 (16 px/字)
           紧凑地址 = slot*60 + ch*20 + word          (slot 0..11, ch 0..2, word 0..19)
           slot = 绝对行号 mod 12  → 每算完一个 tile 环推进 10 行（序列 0,10,8,6,4,2,...）
           读窗口：需要列 [c0-1, c0+10] 共 12 列 → 落在 1~2 个字里，取 12 B

plane    : 视图 P2 = {ch[2:0], row[6:0], word[3:0]}   8ch x 120row x 10 字 = 9600 字
           视图 P4 = {ch[3:0], row[5:0], word[2:0]}  16ch x  60row x  5 字 = 4800 字
           每字 16 B，每行 160 B(P2) / 80 B(P4)
           通道平面化（channel-planar）→ 窗口一次读就是"某通道某行的 16 个连续列"
```

**为什么必须通道平面化**：窗口是 `12 行 x 12 列 x 单通道`，像素交错布局下 12 列跨 12 个字、无法整字取；通道平面化后每行 1~2 个字。

### 3.4 写数据通路（字节使能 + 攒字）

输入池化每拍产 4 个池化像素 = 12 B，且是**像素交错**（px0.r,px0.g,px0.b, px1.r,...），而 band12 是**通道平面**：
→ 每拍把 12 B 解交织进 3 个通道暂存字（各 16 B 里填 4 B），**攒 4 拍 = 每通道 16 B**，再用 3 拍连续写 3 个通道字（3 写 / 4 拍，写口占用 75%，安全）。

写回 plane：每个 tile 的池化结果是 `5x5 x COUT`；**按 oc 立即写**，每行 5 B（字节使能 1 次写）：
- L1：5 行 x 8 ch = **40 次写/tile**（tile 116 拍 → 占用 34%）
- L2：5 行 x 16 ch = **80 次写/tile**（tile 213 拍 → 37%）
→ 这就是省下 `blk[0:63][0:99]`（51,200 FF）的做法。

### 3.5 原地别名：省 60 片（75 KB）的两种方案

通道平面化后，P4 的行只有 80 B（不是 1280 B），所以**别名不再是"行对行"那么简单**，给两个方案：

**方案 A（推荐先用）：不别名**
`P2 = 120 片 + P4 = 60 片 = 180 片`，加上 raw_line+band12 = **190/256 = 74.2%**（243 KB）。
读写指针互不干扰，控制最简单。**第一步/第二步先按这个做。**

**方案 B（省存储）：原地覆盖 + 读后写纪律**
P4 总 75 KB = P2 的一半。把 P2 按 **行块** 排布，使"读顺序 = 地址递增"：
```
P2 行块 j = [ch0 行2j][ch0 行2j+1][ch1 行2j][ch1 行2j+1]...  = 8ch x 2 行 x 160 B = 2560 B
P4 行 r (全 16 通道 = 1280 B) 写到字节 [r*1280, (r+1)*1280) = 落在 行块 floor(r/2) 的范围内
安全条件：行块 floor(r/2) 已被消费完（r/2 <= r 恒成立）；再配合"本 tile 窗口先装完、再写回上一 tile"的纪律，
         写指针永远不碰"本 tile 还要读的行"。
```
→ 130/256 = 50.8%。**代价是控制复杂 + 需要读写指针握手**；跑通 A 之后再切 B。
（第三级要上片时 B 基本是必需的：A 方案 190+120 = 310 > 256 片。）

### 3.6 不进 BRAM 的部分（寄存器窗口）

| 结构 | 规模 | 说明 |
|---|---|---|
| 12x12 单通道窗口 | 144 x 8 bit = 1152 FF | 沿 `feature_map_12_12` 的做法，逐通道装入 |
| 复用链（PE 内） | 3 x 8 bit/PE | 3x3 卷积的垂直重用 |
| dw 通道结果 `dwc` | 8~16 ch x 100 px x 8 bit = 800~1600 B | 8bit 量化后存寄存器（mb2 用 18bit x 32ch = 57,600 FF，**必须砍**） |
| pw 累加器 | 100 px x 24 bit x 2 车道 = 600 B | 按 oc 流式，算完一个 oc 立即池化写回 |
| 池化树阵列输出 | 25 x 8 bit x COUT 在飞 | 两级流水打拍 |

## 4. 计算过程

### 4.1 输入级（DDR → raw_line → 2x2 池化 → band12）

状态机（沿用 `mb2_top` 的 `I_ROW0/I_RX0/I_ROW1/I_RX1/I_POOL` 骨架）：

| 状态 | 动作 | 拍数 |
|---|---|---|
| `I_ROW0` | 发起偶行读：`addr = 2r*1280`，`len = 80` beat，`id = 1` | 1 |
| `I_RX0` | 每 beat：128 bit 直写 `raw_line[beat]` | 80 |
| `I_ROW1` | 发起奇行读：`addr = (2r+1)*1280` | 1 |
| `I_RX1` | 每 beat：读 `raw_line[beat]`（← 偶行 8 px）+ 新到 8 px → **4 个 max4/拍** → 12 B → 暂存/攒字写 band12 | 80 |
| — | 240 次（r = 0..239），每行对 162 拍 → 240 x 162 ≈ 38,880 拍 | |

- 2x2 池化：RGB565 先展开成 R5/G6/B5，**逐通道取最大**再重新打包成 3x8bit（不是对 16bit 打包值取最大）。
- 边界不反射：池化正好整除（640/2=320, 480/2=240），无需 halo。
- 生产速率 = 12 B/拍；band12 写口 16 B/拍 → 有余量。

### 4.2 L1 引擎 tile 调度（10x10 输出，3→8 通道）

沿用 mb2 的**复用卷积模式**（`pe10_10`/`mb2_pe_array` 的 `op=1`）与**交接拍装载**：

| 阶段 | 拍 | 说明 |
|---|---|---|
| `E_PRE` | 4 | 装载 ch0 的 12x12 窗口并 `start` |
| `E_DW` x CIN | 3 x 12 = 36 | `start+1..+9` 按 3x3 光栅序喂 9 个权重；`start+11` 出 9 抽头和；**第 12 拍同时捕获 dwc 并装下一通道窗口** |
| `E_GAP` | 4 | |
| `E_PW` | COUT*CIN + 6 = 8*3+6 = 30 | 点卷积：每 oc 对 3 个 ic 累加 |
| 量化 | 4 | `(acc + 128) >>> 8`，clamp 0..255 |
| **池化融合** | 2 | 10x10 → 5x5：**25 棵 max4 两级流水** |
| `E_WR` | 40 | 5 行 x 8 ch，每行 5 B 字节使能写 plane |
| **合计** | **≈ 120 拍/tile** x 768 tile = **92,160 拍** | |

窗口装载：12 行 x 12 列/通道，横向相邻 tile 只换 10 列 → 12 次 16B 读/通道（36 次/tile），
与 `E_DW` 的交接拍重叠（读口与计算互不抢资源）。

**band12 生产/消费握手**：一个 tile 行（10 行池化面 = 32 tile）消费 32 x 120 = 3,840 拍；
生产 10 个池化行需要 20 个原始行 = 1,600 拍（含池化）。→ 生产比消费快 2.4 倍，会跑在前面；
`band12` 12 行环只允许"领先不超过 10 行"，所以生产者必须在消费者消费完 10 行后才推进环指针（简单握手信号 `rows_free`）。

### 4.3 L2 引擎 tile 调度（10x10，8→16 通道）

| 阶段 | 拍 |
|---|---|
| `E_PRE` | 4 |
| `E_DW` x 8 | 96 |
| `E_GAP` | 4 |
| `E_PW` | 16*8+6 = 134 |
| 量化 + 池化 | 6 |
| `E_WR` | 80 |
| **合计** | **≈ 324 拍/tile** x 192 tile = **62,208 拍** |

窗口装载：8 通道 x 12 次 = 96 次读/tile（从 plane 读），与 dw 重叠。

### 4.4 L3（可选，80x60x16 → 80x60x32）

`4 + 12*16 + 4 + (32*16+6) + 80 + 2` = **462 拍/tile** x 48 tile = **22,176 拍**。

### 4.5 帧级时间预算

| 级 | tile 数 | 拍/tile | 拍 |
|---|---|---|---|
| 输入 DMA + 池化 | 240 行对 | 162 | 38,880（可与 L1 重叠） |
| L1 | 768 | 120 | 92,160 |
| L2 | 192 | 324 | 62,208 |
| L3（可选） | 48 | 462 | 22,176 |
| **合计（3 级）** | | | **≈ 176,544 拍 ≈ 0.88 ms @200MHz** |
| 串行加上输入级 | | | **≈ 215,424 拍 ≈ 1.08 ms** |

对比上一版 361,344 拍（1.81 ms）：**快 2 倍**，主要来自通道数从 16/32 降到 8/16、以及池化完全融合。

### 4.6 池化比较树阵列（你要求的那个模块）

```
conv_cmp4_tree #(.W(8))            // 单棵 4 输入比较树，两级流水打拍
   ├ stage1: r1a = max(a,b), r1b = max(c,d)   ← 打拍 1
   └ stage2: r2  = max(r1a,r1b)               ← 打拍 2（附带 valid 两拍）

conv_pool_arr #(.ROWS(5), .COLS(5))  // 参数化阵列 = ROWS*COLS 棵
   100 个 W bit 输入 → 25 个 W bit 输出，整体两级流水
   输入池化用 1x4 例化（+ RGB565 展开 3 通道：R5/G6/B5 三棵树一组）
   后面 10x10→5x5 用 5x5 例化（每通道一组：L1 8 组、L2 16 组）
```

输入池化：每拍 4 个池化像素 x 3 通道 = 12 棵小树（R/G/B 位宽分别 5/6/5）。

### 4.7 DUAL 模式两次 8bit MAC 的位打包（已在原语里确认）

`rtl/dsp48/efx_dsp48.v`：
```
MODE="DUAL" → A[18:8] x B[17:8] (11x10) → O[36:16]
              A[ 7:0] x B[ 7:0] ( 8x8) → O[15: 0]     ← 两个部分积完全不重叠
加法器常量 CONST1 = 48'h000001_000001 → 两个 24bit 累加车道
```
- PE 里把两个像素（或两个抽头）放 `A[7:0]` 和 `A[18:8]`，权重放 `B` 对应位段，即可一拍两次 MAC，各自累加到 24bit。
- 24bit 够不够：8bit 无符号乘积 ≤ 65025；dw 9 抽头 ≤ 585,225 ✓；pw 最多 16 通道 ≤ 1.04 M ✓（24bit = 16.7 M，余量充足）。
- 收益：`E_DW` 的 12 拍/通道 → 约 7 拍，`E_PW` 的 `COUT*CIN+6` → 约一半。整帧 189k → **129k 拍（0.65 ms）**。

## 5. 资源消耗量分析

### 5.1 上一版实测基线（说明"钱花在哪"）

| 模块 | FF | LUT | RAM | DSP |
|---|---|---|---|---|
| `mb2_pe_array`（100 个 18bit PE） | 19,036 | **56,707** | 0 | 100 |
| 三个平面缓存（`mb2_plane`+`mb2_cache`） | ~2,600 | ~7,400 | 160 | 0 |
| `feature_map_12_12` | 1,163 | 3,460 | 0 | 0 |
| 顶层 dwc/blk/pacc 寄存器堆 | **113,600** | — | 0 | — |
| 器件 | 60,800 | 60,800 | 256 | 160 |

两个结论：① **PE 阵列的 LUT 是最大头（567 LUT/PE）**，因为 18bit 数据 + 可变 kernel_width/height 选择树；② **FF 爆表**（113,600 FF 的中间寄存器堆）。

### 5.3 可行性判定

| 项 | 判定 | 说明 |
|---|---|---|
| BRAM | ✅ 可行 | 二两级 130 片（51%）余量充足；三级 250 片（97.7%）偏紧，建议 L3 输出回 DDR 或只做二级 |
| FF | ✅ 可行 | 24k/60.8k = 40%（上一版 230% 是致命项，本方案靠"平面进 BRAM + 按 oc 立即写回 + 8bit 累加"解决） |
| LUT | ⚠️ 需实测 | 26.5k~34.5k（44~57%），**成败取决于新 PE 的真实 LUT**（对比老 PE 567 LUT） |
| DSP | ✅ 可行 | 100/160，余 60 给第二排 PE 或 DUAL 扩展 |
| 时间 | ✅ 可行 | 二两级 ≈ 0.63 ms/帧，三级加输入 ≈ 1.08 ms/帧 @200 MHz |
| 带宽 | ✅ 可行 | BRAM 读写总量 ≈ 0.8 MB/帧（≈ 50k 拍），计算 176k 拍，读写完全藏得住 |

### 5.4 三个风险点与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| **单 PE 的 LUT 大小**（最大不确定项） | 100 PE 若按 567 LUT → 56.7 k LUT 直接爆 | 先用 `pe_test` 流程把 8bit DUAL PE map 一遍拿实数；若 >300 LUT/PE，减到 5x10 阵列或把复用选择树做成固定 3x3 |
| 三级 RAM 97.7% 无余量 | 后期加层放不下 | L3 输出写 DDR；或 L2 输出保持 16ch 不分两半 |
| 原地别名的读写纪律 | 静默数据错 | 第一版用不别名（190 片 = 74%）；别名版必须"本 tile 窗口先装完再写回上一 tile" |

## 6. 分步实施

| 步 | 内容 | 验收 |
|---|---|---|
| 0 | 用 `pe_test` 流程标定 **8bit DUAL PE** 的真实 LUT/FF/时序 | `efx_map` 资源报告：LUT/PE、DSP=1 |
| 1 | `rtl/conv`：`conv_cmp4_tree` + `conv_pool_arr`(5x5/1x4) + `conv_raw_line`/`conv_band12` IP 生成脚本 + 输入 DMA（DDR→2x2→band12）+ TB/`filelist.f`/`sim.do`/`run.bat` | ModelSim 逐字节自检 PASS（黄金模型比对 320x240x3 带） |
| 2 | L1 引擎 + plane（不别名 180 片）+ 端到端 `160x120x8` 自检 | 与软件黄金模型逐字节一致 |
| 3 | L2 引擎 + 原地别名优化（130 片）+ 三级评估 | 资源/时序报告 + 别名安全回归用例 |

### 第一步的切分（已被器件定死）

DDR 每拍 8 px → 2 行 x 8 列 = **4 棵 max4/拍 = 4 个池化像素/拍**（12 B/拍）。
"每拍 96 个像素"不可行也不必要：单读口最宽 64 px/拍，DDR 只给 8 px/拍，且 96 不整除 640。

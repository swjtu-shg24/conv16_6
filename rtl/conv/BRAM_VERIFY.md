## 1. 原语事实

- 一片 `EFX_RAM10 / EFX_DPRAM10` = **10,240 bit**，原生模式：
  `512x20 / 512x16 / 1024x10 / 1024x8 / 2048x5 / 2048x4 / 4096x2 / 8192x1`
- 宽字靠**多片并联切片**实现，片数写进生成文件的 `bram_decompose.vh`：
  | 现成 IP | 形状 | `bram_mapping_size` | 数据 | 位效率 |
  |---|---|---|---|---|
  | `ram_1024_64` | 1024 bit x 64 | **52** | 8 KB | 12.4% |
  | `ram_512_64` | 512 bit x 64 | **26** | 4 KB | 12.4% |
  | `bram_1KB` | 8 bit x 1024 | **1** | 1 KB | **80%** |
- 切片模式：`Data Width = 20, Addr Width = 9`（512 深）→ 理想片数 ≈ `ceil(W/20) * ceil(D/512)`。

## 2. Efinity 实测（`rtl/conv/memtest/memtest_top.v`，1.2 秒跑完）

| 实例 | 形状 | 实测片数 | 位效率 | 备注 |
|---|---|---|---|---|
| u_a | 128 x 120 bit | 6 | 25% | 20 bit 切片，深度只用 128/512 |
| u_b | 80 x 128 bit | **7** | 14% | 同上（浅存储器最亏） |
| u_c | 1536 x 60 bit | 12 | 75% | 工具用 10 bit 切片 x 2 段 |
| u_d | 160 x 48 bit | 3 | 25% | |
| u_e | 1024 x 8 bit | **1** | **80%** | ★ 唯一"又好又便宜"的形状 |
| u_f | 10240 x 120 bit | **240** | 50% | 工具退化成 `READ_WIDTH=1` 切片 |

## 3. 三个必须避开的坑

1. **不要用宽字**：宽度按 `ceil(W/20)` 成倍吃片，浅存储器（几百字）效率只有 14~25%。
2. **深 + 宽会触发工具的退化映射**：`10240x120` 被判成 120 个 `8192x1` 片 x 2 段 = 240 片。
3. **怪形状会让综合器崩**：第二轮标定（7680x40 + 1536x20 + 160x48 + 1024x16 + 512x20 同时推断）直接 `EXCEPTION_ACCESS_VIOLATION`。→ 结论：**只用 1024x8 这种最普通的形状**，别让工具做形状决策。

## 4. 修正后的存储架构（只用 `1024 x 8` 字节宽 bank）

| 缓冲 | 数据量 | 结构 | 片数 | 可装载率 |
|---|---|---|---|---|
| 输入原始行缓存 | — | **取消**：DDR 里偶/奇两行交错突发读入 → 小寄存器 FIFO 做 2x2 池化 | **0** | — |
| `band12`（12 行 x 320 px x 3ch） | 11,520 B | **16 bank** x `1024x8`（每 bank 720 B） | **16** | 70% |
| `plane`（160x120x8，兼 80x60x16） | 153,600 B | **16 bank** x 10 片（每 bank 9,600 B） | **160** | 93.75% |
| **合计** | 165 KB | | **176 / 256 = 69%** | |

- **bank = 地址低 4 位**（2 的幂，无除法）：一次访问 = 16 个连续字节；窗口取 12 列只需 1~2 次访问；池化写入 12 B/拍刚好一次访问装下。
- 每片用量：`1024 x 8` 模式用 8,192 bit / 10,240 = **80% 位效率**（这是拿"简单 + 可预测"换来的，可接受）。
- **三级复用（关键）**：`P2(150 KB)` → 池化后就地变 `P4(75 KB)` → L3 就地变 `P5(150 KB)`，全部落在同一块 160 片里，**不额外占片**。
  安全性同前一版论证：`P4` 行 r 写 `P2` 行 r 的地址，而产生 `P4` 行 r 时已消费到 `P2` 行 `2r+2` → 写指针永远落后读指针 ≥2 行。

## 5. 代价与取舍

| 取舍 | 说明 |
|---|---|
| 取消行缓存换 DDR 双读 | 输入 DDR 流量 x2（614 KB → 1.23 MB/帧 = 76,800 beat ≈ 0.38 ms @200MHz），换来 0 片 BRAM 和一块 10,240 FF 的寄存器。输入级仍比 L1（92k 拍）快 |
| 备选：保留行缓存 | 16 bank x `1024x8`（每 bank 80 B）= 16 片，省掉 DDR 双读；两种都可，建议先做"双读"版 |
| 位效率 80% | 想榨到 100% 得用 20 bit / 40 bit 宽字，但实测 60 bit 只有 75%、120 bit 只有 50% → 不划算 |

## 6. 受影响的旧结论

- **作废**：`DESIGN.md` §3.1 的片型表、§3.2 的 130 片预算、§3.3 的 120 bit 宽字地址映射、§5.2 表的 RAM 列；`BRAM_PLAN.md` 的"128 bit=1280 B=100%"与"一片顶 16 bank"。
- **保持有效**：FF 爆表分析（139,847 > 60,800）、DSP48 `DUAL` 两次 8bit MAC、拍级调度与时间预算（~189k 拍/帧）、按 oc 立即池化写回、12 行带/10 行推进、窗口分拍装载。

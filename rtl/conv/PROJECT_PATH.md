## 一、目标

| 项 | 内容 |
|---|---|
| 器件 | Efinix **Ti60F225**（工程名 `conv10_10`） |
| 输入 | DDR 里**已池化好的 `320×240×3`**（RGB888，8bit/ch） |
| 输出 | **`160×120×8`**（到这一级为止） |
| 计算 | L1 = `dw3×3` + `pw1×1` + 量化 + 与 `2×2 max` 池化融合 |
| tile | 输入面 10×10 一块 ⇒ 需要 12×12 的输入窗口（含边界反射） |
| tile 数 | 32 × 24 = **768** |

输入行布局（DDR）：`base + row*960 + { R[320], G[320], B[320] }`，共 240 行 = 230,400 B。

## 三、PE 阵列接口契约（用户原话，逐条遵守）

来自 `pe_10_10_tb.v` 里的注释：

```verilog
//op拉高为复用数据，拉低为直接相乘
//关闭阵列: op拉高，不发start位
//完成一次复用卷积:op拉高，发送一次start脉冲，计算过程中，op不能拉低，start不能重复发送脉冲
//完成一次直接相乘: op拉低,需要同时加载计算数据(放在左上的16*6区域)
//数据可以加载与start位同时变换
```

| 规则 | 含义 |
|---|---|
| `op=1` | 复用卷积模式（数据复用） |
| `op=0` | 直接相乘模式 |
| 关闭阵列 | `op=1`，**不发 `start`** |
| 一次复用卷积 | `op=1`，**发一次 `start` 脉冲**；期间 **`op` 不能拉低**、**`start` 不能重复发** |
| 一次直接相乘 | `op` 拉低，**同时加载数据**（左上 16×6 区域）；数据加载与 `start` 位同时变换 |

## 四、已验证的时序事实（都是实测，不是推导）

### 4.1 复用卷积（`op=1`）

| 事实 | 测法 |
|---|---|
| `wdata_en` + `op` + `start` **同拍**拉高 | 照 `pe_10_10_tb.v` 的写法复现 |
| `peo` 起于第 2 拍 | 逐拍打印 |
| **第 10 拍 = 正确 3×3 加权和** | 窗口 `(r+1)*10+(c+1)`、权重 1..9，`peo[0]` 在第 10 拍 = **198** |
| 第 11 拍起继续累加（脏） | 逐拍表：198 → 231 → 264 |

**驱动相位与结果的关系**（关键，用并排对照表测的）：

| 相位 | `peo` 序列 | 198 出现在 |
|---|---|---|
| `wdata_en`+`start` 同拍 | 11, 23, 36, 57, 79, 102, 133, 165, **198** | 第 8 拍 |
| `start` 比 `wdata_en` 晚 1 拍 | 0, 11, 23, 36, 57, 79, 102, 133, 165, **198** | 第 9 拍 |

> **结论**：两种相位都能得到正确的 198，只是**累加窗口整体平移**。
> 所以实现时选一种相位，然后把"抓数拍"对着它定死即可。

### 4.2 PE 内部窗口搬运的正确形态

正确的 `input_reg_a[0]`（PE 真正拿到的值）序列：

```
13, 21, 22, 23, 31, 32, 33, 34, 35, 36, 37, 38, ...
 └─列0─┘ └─列1的3行─┘ └─列2的3行─┘ └─列3...
```

即**"一列 3 个（3 行）+ 换列 +10"**。
如果看到的是 `233, 240, 240, 247, 247, ...`（逐列 +1 前进），说明窗口搬运错了。

### 4.3 直接相乘（`op=0`）

| 事实 | 测法 |
|---|---|
| `op=0`、`load_a_in_opt` **常高**、`input_en` **常高**、a/b 每拍换 | `peo` **落后 2 拍、且每拍都是新乘积** |
| 8 次背靠背喂 (a,b) | 每次都能拿到正确 `a×b` ⇒ **1 MAC/拍 可行** |
| `load_a_in_opt` 单拍脉冲、a/b 钉住 | 脉冲后 **+1 拍**可读，**+3 拍**被清零 |

> **结论**：pw 相位可以**流式**做，1 拍 1 个乘积 ⇒ `CIN*COUT = 24` 拍够用。

### 4.4 输出使能

| 信号 | 关系 |
|---|---|
| `output_en` | `input_en` 后 **2 拍**；拉高那一拍 `PE_output` 就是当前数据 |
| `out_type` | `op` 后 **3 拍**；**不做模式区分**，两种模式走同一套输出 |

> `output_en` 可以作为"数据有效"的抓取使能。

### 4.5 `feature_map_12_12` 的 autoload（最大的坑）

`feature_map_12_12` 内部有一个 9bit `start_reg` 移位寄存器：

```verilog
always @(posedge clk)
    if (rstn) begin
        if (start) start_reg <= 9'd1;
        else       start_reg <= {start_reg[7:0], 1'b0};
    end
```

- `start_reg[0]` → `load_a_in_opt`（PE 的 `input_reg_a[0]` **装载脉冲**）
- `start_reg[2]/[3]/[6]` → `buttom_a_in_last_line`（**行自动装载**）
- `start_reg[1]/[2]/[4]/[5]/[7]/[8]` → `right_a_in_last_line`

**坑**：`start_reg` 每一位都会让 `load_a_in_opt` 或 `buttom_a_in_opt` 脉冲一次，
而 **`load_a_in_opt` 脉冲会把 `input_reg_a[0]` 重装、累加器清零**。

| 症状 | 原因 |
|---|---|
| `peo` 出现 `180 → 373 → 579 → 180` 的 4 拍循环 | `start_reg[4]` 命中了 `load_a_in_opt` |
| `input_reg_a[0]` 逐列 +1 前进（不是"行内3个+换行"） | autoload 相位错位 |

**规避办法（二选一）**：
1. **按契约给 `start`**（一次复用卷积只发一次、`op` 不拉低）—— 实测这样 `start_reg` 的相位和用户 tb 一致
2. 或**自己写窗口映射**，不用 `feature_map_12_12`（`pe.v`/`pe_10_10.v` 仍不动）

## 五、存储方案

### 5.1 片型

只用 `ip/bram_10kb`：SDP，**512 字 × 20 bit**，1 片 = 1,280 B。
一个 **unit = 40 bit = 5 字节 = 2 片同址并联**。
Ti60F225 共 **256 片 = 320 KB**。

### 5.2 输入环缓冲 `conv_band`（12 行）

| 项 | 值 |
|---|---|
| 结构 | 6 bank × 2 段 × 512 unit = 6,144 unit |
| 片数 | 6 × 2 段 × 2 片 = **12 片** |
| unit 布局 | `u = slot*(3*CPU) + ch*CPU + k`，`CPU = IW/5 = 64` |
| 行内 | 320 像素 = 64 unit/通道；3 通道 = 192 unit/slot |
| 地址 | `bank = u mod 6`、`addr = {seg, u/6 mod 512}`，**用计数器做，不做除法** |
| 字节序 | unit 内低到高：`col0, col1, col2, col3, col4` |
| slot | `row mod 12`（计数器维护） |

### 5.3 输出面 `conv_plane`（160×120×8）

| 项 | 值 |
|---|---|
| 结构 | 6 bank × 10 段 × 512 unit = 30,720 unit = **153,600 B** |
| 片数 | 6 × 10 × 2 = **120 片** |
| 布局 | `unit = ((oc*OH + row)*OW + col)/5`，`OH=120, OW=160` |
| 每行 | 160 B = 32 unit，一个 oc = 3,840 unit，8 个 oc = 30,720（100% 塞满） |

### 5.4 片数预算

```
输入环缓冲（12 行）  =  12 片
输出面（160×120×8）  = 120 片
------------------------------
合计                 = 132 片 / 256 片（51.6%）
余量                 = 124 片（可留给 L2/L3 原地复用或 ping-pong）
```

## 七、conv_l1 的相位与拍数

### 7.1 相位表（`CIN=3, COUT=8`）

| 相位 | 拍数 | 做什么 |
|---|---|---|
| `S_WAIT` | 等 | `win_req` 要窗口；`win_vld` 到 → 发 `start`（一次） |
| `S_DW` | 每个 cin 10 拍 × 3 = **30** | 第 t 拍喂 `w_dw[cin*9+t]`；**第 10 拍抓 100 个 `peo`** |
| `S_PW` | 24 喂 + 2 排空 = **26** | 背靠背喂 24 个 `(oc,cin)`；第 k 拍喂 → 第 k+2 拍收到 |
| 量化 | 每个 oc 1 拍 × 8 = **8** | `(acc+128)>>>8`，clamp 0..255 |
| 池化 | 每个 oc 2 拍 × 8 = **16** | 25 棵两级流水，第 2 拍结果有效 |
| 写回 | **40** | 8 oc × 5 行，每行 5B = 1 unit |
| **合计** | **≈ 120** | 768 tile ≈ 92k 拍 ≈ **0.46 ms @200MHz** |

> 目标 `CIN*9 + CIN*COUT = 51` 是"纯 MAC 拍数"。
> 上面的 120 拍里含窗口装载、量化、池化的开销；
> 其中**窗口装载可以与计算 ping-pong 重叠**（双缓冲），重叠后能压到 ~90 拍的量级。

### 7.2 关键相位（务必照做）

```
窗口锁存那一拍  t0 :  wdata_en=1, op=1, start=1     ← 三者同拍
                    ↓ （feature_map 在这一拍把 144 个数锁进去）
第 t0+1 起        :  op 保持 1，start 回 0（不能再发）
第 t0+2 起        :  peo 开始出乘积
第 t0+10          :  peo = 正确的 3×3 加权和   ← 抓数
```

**pw 相位**：
```
op=0, load_a_in_opt=1, input_en=1（都要保持）
第 k 拍喂 (a=dwq[ic][像素], b=w_pw[oc*CIN+ic])
第 k+2 拍 peo 就是该乘积  → 立刻累加
```

## 八、实现路径（分步，每步都要能验证）

> **纪律**：每一步先写 tb、先拿到"期望值"，再写 RTL。
> 不允许"改 RTL → 看波形 → 再改"这种循环。

### 第 1 步：PE 阵列驱动封装（0.5 天）

**目标**：把用户契约变成 3 个可复用的任务/模块，不碰内部。

```
task pe_reuse_start;   // op=1，发一次 start（与 wdata_en 同拍）
task pe_reuse_capture; // 第 10 拍抓 100 个 peo
task pe_direct_feed;   // op=0，流式喂一个 (a,b)
```

**验证 tb**：`tb_pe_spec.v`
- 窗口 `(r+1)*10+(c+1)`，权重 1..9
- 期望：第 10 拍 `peo[0]=198`、`peo[99]=396`
- 期望：pw 背靠背 8 次，每次 `peo = a×b`
- **判据**：两组全对

### 第 2 步：池化树（0.5 天）

**验证 tb**：`tb_pool.v`
- 随机 10×10、边界 0/255、全同值 三组
- 期望：25 个逐点相等、流水 2 拍
- **判据**：mismatch = 0

### 第 3 步：conv_l1 的 dw 相位（1 天）

**验证 tb**：`tb_l1_dw.v`
- 只跑 dw，用真实图像窗口，权重 1..9
- 期望：`dwq[c][0]` = 黄金量化值（`(sum+128)>>8`）
- **判据**：三个通道全部相等
- **失败排查顺序**：
  1. `start_reg` 相位是否和参考一致（第 4.1 节的两种相位选一种）
  2. `input_reg_a[0]` 是否是"行内3个+换行"（第 4.2 节）
  3. `load_a_in_opt` 是否全程为 0（第 4.5 节）

### 第 4 步：conv_l1 的 pw 相位（0.5 天）

**验证 tb**：`tb_l1_pw.v`
- 先用已知的 `dwq`（直接写死），跑 pw
- 期望：`acc[oc][p] = Σ_c dwq[c][p] * w_pw[oc*3+c]`
- **判据**：8 个 oc × 100 像素全部相等

### 第 5 步：conv_l1 整片（1 天）

**验证 tb**：`tb_l1.v`
- 小图 `80×40×3` → tile(1,1)，8oc × 5×5
- 期望：逐点等于黄金模型
- **判据**：mismatch = 0，且跑到 `done`

### 第 6 步：窗口装载（0.5 天）

**验证 tb**：`tb_win.v`
- 把已知数据写进 band → 读 12×12 窗口
- 期望：逐字节等于"输入面 + 反射"算出来的窗口
- **判据**：3 个通道 × 12×12 全部相等
- **注意**：反射规则 `-1 → 1`、`N → N-2`

### 第 7 步：输入 DMA（0.5 天）

**验证 tb**：`tb_dma.v`
- DDR 模型给已知图案 → 检查写进 band 的每个 unit
- 期望：`unit = slot*(3*CPU) + ch*CPU + k`，5 字节逐字节正确
- 期望：信用流控不冲掉未消费的行
- **判据**：整行 192 unit 全对

### 第 8 步：conv_top 顶层（1 天）

**验证 tb**：`tb_top_small.v`
- 小图 `80×40×3` → `40×20×8`
- 期望：`done` 到达 + 全帧逐点等于黄金模型
- **判据**：mismatch = 0

### 第 9 步：整帧回归（0.5 天）

**验证 tb**：`tb_top_full.v`
- 整帧 `320×240×3` → `160×120×8`
- **判据**：`done` 到达 + 抽样比对（全比对太慢）

**总计 ≈ 6 天**

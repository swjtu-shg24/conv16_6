# MobileNet 前端（10×10 PE 阵列，3 级 dw3×3 + pw1×1）

> 目标：把 `640×480×3` 一路算到**第一个残差块之前**（`80×60×64`），
> DDR **只读一遍**，所有中间结果留在片上，**不做重算**。
> 本文档 = 架构 + 模块职责 + 时序契约 + 波形变量含义 + 实测数据 + 怎么跑。

---

## 0. 一句话结论（已仿真验证）

### 真实目标 640×480（当前版本 = **流水线融合版**）

```
LB0 mismatches = 0                 输入 2x2 max 池化面 320x240x3
LB1 (L1 out, pooled) mismatches = 0  第1级 dw3x3+pw1x1 -> 池化 160x120x16
LB2 mismatches = 0                   第2级 -> 池化 80x60x32
=== image 640x480 -> front-end result 80x60x64 = 307200 bytes, mismatches = 0 ===
MB2 RESULT: PASS        SIM cycles = 388349  (≈1.94 ms @200MHz)
ModelSim: 0 Errors, 0 Warnings
```

**融合点**（相对"级串行 + 独立池化遍 + 阻塞输入"版）：

| | 串行版 | 融合版 |
|---|---|---|
| 池化 | 两遍独立状态，把上一级输出面读回来，5 拍/像素 | **比较树融进写回**：量化输出的 10×10 过 25 个 4 输入比较树 → 5×5，只加 2~3 拍；写回 100 字 → **25 字** |
| 中间平面 | L1O/L2O/L3O 三块全分辨率面 | **L1O/L2O 不存在了**（直接写池化后的 LB1/LB2） |
| 输入 | 阻塞阶段，全部做完才进 tile | **独立并发 FSM**（自己读 DDR + 2×2 max + 1 列/拍写 LB0），执行器只在行没到齐时停一下 |
| 拍数 | 647,618 | **388,349**（1.66×） |

剩下的 ~27,000 拍是输入生产者的吞吐造成的（它 ~490 拍/行 > L1 消耗的 400 拍/行）：
**池化改成 2 列/拍**（或两行并行读）→ ≈361,344 拍 ≈ **1.81 ms @200 MHz**。

### 缩比 160×160（快测，`+define+MB2_SMALL`）

```
LB0/LB1/LB2/输出 mismatches = 0        SIM cycles = 34041（串行版 54990）
```

黄金模型和 RTL **共用同一份权重/像素展开函数**（`mb2_wdef.vh`），所以权重不可能对不上。

> **tile 行/列数不能搞混**：`T*R = 高/10`、`T*C = 宽/10`。
> 方形图（160×160）时两者相等，写反了看不出来；640×480 时写反会让
> `c ≥ 240` 整片区域根本没被处理（实测 L1O 第一处 mismatch 正好在 c=240）。
>
> **"要等的最远行"必须在平面末尾截断**：L1 最后一个 tile 行的窗口行号是
> `10*(T1R-1)+10 = 80`，已经越过平面（靠反射补），就绪条件不截断会**死等到超时**。

## 1. 数据流（含真实数字）

```
DDR(顺序读一遍, 每行 IMG_W/8 个 128bit beat)
  │
  ├─ 2x2 maxpool ──────────────► LB0   80x80x3     (含 3 通道, 24bit/像素)
  │                                   │  12x12 窗口(越界反射 -1->1, N->N-2)
  │                                   ▼
  ├─ dw3x3 + pw1x1 (3→16) ─────► L1O   80x80x16    (128bit/像素)
  │                                   │
  ├─ 2x2 maxpool ──────────────► LB1   40x40x16
  │                                   │
  ├─ dw3x3 + pw1x1 (16→32) ────► L2O   40x40x32    (256bit/像素)
  │                                   │
  ├─ 2x2 maxpool ──────────────► LB2   20x20x32
  │                                   │
  └─ dw3x3 + pw1x1 (32→64) ────► L3O   20x20x64    ★前端结果
```

对应 640×480：`320×240×3 → 320×240×16 → 160×120×16 → 160×120×32 → 80×60×32 → 80×60×64` ★
即用户给出的 `640*480*3 -> 320*240*3 -> 320*240*16 -> 160*120*16 -> 160*120*32 -> 80*60*32 -> 80*60*64`，
**到 `80*60*64` 正好是残差块之前**。

每一个 10×10 tile（覆盖率 10×10 像素）需要输入面 **12×12 窗口**（多 1 圈给 3×3 卷积），
边界用反射：`-1 → 1`，`N → N-2`（`mb2_lb` 内部 `irr/icr/cc/rr` 显式有符号算出来）。

tile 排布：`ir = 0..平面高/10-1`，`ic = 0..平面宽/10-1`；
tile `(ir,ic)` 的窗口起点 = 原面坐标 `(10*ir-1, 10*ic-1)`。

| 级 | 输入面 | CIN | COUT | tile 数(160×160) | tile 数(640×480) |
|----|--------|-----|------|------------------|------------------|
| L1 | LB0 80×80   | 3  | 16 | 8×8 = 64  | 32×24 = 768 |
| L2 | LB1 40×40   | 16 | 32 | 4×4 = 16  | 16×12 = 192 |
| L3 | LB2 20×20   | 32 | 64 | 2×2 = 4   | 8×6  = 48   |

## 2. 时序契约（`mb2_cal_tb` / `mb2_cal_b_tb` 实测标定，不是猜的）

### 2.1 数据复用模式（dw 3×3，`op=1`）

以 `start` 那一拍为 T0（该拍同时把 12×12 窗口写进 `feature_map`）：

| 拍 | 事件 |
|----|------|
| T0 | `wdata_en=1` + `start=1`，窗口进 feature_map |
| T0+1 … T0+9 | 权重按 **3×3 光栅序** 喂 9 个：`w = wd(ch, k)`，`k = dcy` |
| T0+3 … T0+11 | 9 个抽头依次进入累加器 |
| T0+11 结束 | `PE_output` = 完整 9 抽头和 |
| T0+12 | 捕获 `dwc` **并且**同一沿装载下一通道的窗口+start |

→ **每通道 12 拍**，`CIN` 个通道 = `12*CIN` 拍。
标定数据（全 1 权重，窗口 52,53,54,64,65,66,76,77,78）：`cy=11 → 585`（=9 抽头全和）。

**关键坑**：每个 tile 的**第一个**通道，窗口装载沿必须和其它通道一致，
否则抽头序列整体晚一拍、9 抽头只累到 8 个（实测 `1375` 而不是 `1557`）。
本设计用 `E_PRE`（4 拍空转，`op` 预置 1）在**末拍**装载第一通道窗口来对齐。

### 2.2 1×1 点卷积（`op=0`）

| 拍 | 事件 |
|----|------|
| T | `present`：A=`dwc[pc_c][px]`（每 PE 一个像素），B=权重（全体广播） |
| T 沿 | PE 锁存 A/B |
| T+2 | 乘积出现在 `PE_output` |
| T+3 | `pacc` 累加（`s3v && s3c`） |
| T+4 | 量化写 `blk`（`s4v && s4c==CIN-1`） |

实测（`mb2_cal_b_tb`：A(cy)=cy+1, B=3）：`cy=3 → 3`、`cy=4 → 6`、…、`cy=13 → 33` ⇒ 乘积延迟 2 拍。

> 老的两级设计里 `pacc` 用的是"延迟 2 拍"，因为当时权重全 1，这个偏差看不出来；
> 本设计用**稀疏但有区分度**的权重，必须用延迟 3/4。

### 2.3 一个 tile 的执行开销（实测吻合）

```
E_PRE 4  +  dw 12*CIN  +  E_GAP 4  +  pw COUT*CIN + 6  +  写平面 100  +  ~2
L1: 4 + 36 + 4 + 48  + 6 + 100 + 2 = 200 拍
L2: 4 +192 + 4 + 512 + 6 + 100 + 2 = 820 拍
L3: 4 +384 + 4 +2048 + 6 + 100 + 2 = 2548 拍
```
160×160 全链路实测 **54,990 拍**（≈0.27 ms @200 MHz）。

## 3. 模块职责

| 文件 | 职责 |
|------|------|
| `mb2_top.v` | 顶层：主 FSM（输入→L1→池化→L2→池化→L3）+ 执行器（dw/pw 子状态机）+ 级参数译码 + 六块平面缓冲的读写仲裁 |
| `mb2_lb.v` | **平面缓冲**：整字存（一个像素的 CH 个通道打成一字）。一个整字写口、一个 12×12 窗口读口（单通道，越界反射）、一个像素读口（池化用） |
| `mb2_pe_array.v` | 10×10 PE 阵列：连线与用户 `rtl/pe10_10/pe_10_10.v` 完全一致（水平/垂直复用链），内部例化现有 `rtl/pe/pe.v`（48bit 输出） |
| `mb2_wrom.v` | 权重 ROM 4096×8bit（Q0.8 正整数），组合读；综合时应换 BRAM+提前一拍 |
| `mb2_wdef.vh` | 权重地址/取值 + RGB565→8bit 展开函数，**RTL 与 TB 共用**，保证两边一致 |
| `feature_map_12_12.v` | （用户已有）12×12 窗口寄存器 + `start_reg` 注入调度 |
| `mb2_tb.v` | 自检 TB：DDR 模型 + 黄金模型，六个面逐字节比对 |
| `mb2_cal_tb.v` | 复用模式标定：单点权重法测出"权重第几拍对应窗口哪个 (r,c)" |
| `mb2_cal_b_tb.v` | 点卷积模式标定：测出 present→乘积的拍数 |
| `mb2_probe_tb.v` | 快速探针（无黄金模型），看内部信号、写次数、量化次数 |

### 执行器子状态

| 状态 | 作用 | 拍数 |
|------|------|------|
| `E_PRE` | `op` 预置 + **对齐第一通道窗口装载沿** | 4 |
| `E_DW` | 逐通道深度卷积，`dcy` 0..11，第 11 拍捕获 `dwc` 并交接 | 12×CIN |
| `E_GAP` | `op` 1→0 过渡 | 4 |
| `E_PW` | 连续 present，`pcy` 数到 `COUT*CIN+6` | COUT×CIN+6 |
| `E_WR` | 把 `blk[COUT][100]` 按 10×10 写进目标面 | 100 |

## 5. 一组真实数据（可直接对着波形看）

**输入池化**（LB0）：源像素按 `n = y*IMG_W+x` 线性递增
`R5=n&31, G6=(n>>2)&63, B5=(n>>1)&31`，展开 `R=8*R5+(R5&7)` 等。
`LB0(0,0) = 0x000080` → R=0x80=128, G=0, B=0（2×2 max 挑到了 R 最大的那个）。

**第 1 级 tile(0,0)、PE(5,5)、通道 0 的 dw 累加过程**（波形上 `dcy` 逐拍看）：

| dcy | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 | 11 |
|-----|---|---|---|---|---|---|---|----|----|
| 累加抽头 | 164 | 173 | 182 | 164 | 173 | 182 | 164 | 173 | **182** |
| `peo[55]` | 164 | 337 | 519 | 683 | 856 | 1038 | 1202 | 1375 | **1557** |

窗口 3×3 = `[164 173 182; 164 173 182; 164 173 182]`（光栅序），和 = **1557** ✓
（`dcy=11` 结束后 `PE_output` 就是这个数，下一沿被 `dwc[0][55]` 捕获。）

**第 1 级输出**：`L1O(0,0)` 的 16 个通道 = `ch0..15 = [19, 5, 0, 19, 5, 0, 19, 5, 0, 19, 5, 0, 19, 5, 0, 19]`
（体现点卷积权重"每 oc 只让 2 个输入通道起作用"的稀疏设计，通道接线错了一定会被抓到）。

**池化**：`LB1(0,0)` 取 `L1O` 的 `(0,0)(0,1)(1,0)(1,1)` 四像素逐通道 max。
**第 2 级输出**：`L2O(0,0)` 32 通道 = `ch31..0 = [7,2,0,3,2,0,6,2,0,3,2,0,6,2,0,3,7,2,0,3,2,0,6,2,0,3,2,0,6,2,0,3]`。
**最终结果**：`L3O(0,0)` 64 通道 = `[2,1,0,1,1,0,2,1,...]`。

## 6. 资源与时间

### 6.1 160×160（仿真实测）
- 周期 **54,990**（≈0.27 ms @200 MHz）
- 片上（仿真寄存器阵列）：LB0 19.2 kB、L1O 102.4 kB、LB1 25.6 kB、L2O 51.2 kB、LB2 12.8 kB、L3O 25.6 kB
  → 合计 ~231 kB（仿真用全平面存，方便看波形）
- 权重 ROM 4 kB；PE 阵列 100 个 DSP48 + 100×18bit A 寄存器 + `dwc` 32×100×18bit

### 6.2 640×480（**已实测，不是估算**）
| 部分 | 周期 |
|------|------|
| L1 768 tiles × 200 | 153,600 |
| L2 192 tiles × 820 | 157,440 |
| L3 48 tiles × 2548 | 122,304 |
| 输入流式读+池化（240 输出行） | ~119,000 |
| 中间池化（160×120 + 80×60，5 拍/像素） | ~120,000 |
| **实测合计** | **647,618 ≈ 3.24 ms @200 MHz**（≈1.62 ms @400 MHz） |

DDR 读 = 480 行 × 640 px × 2 B = **614,400 B（正好一遍）**。
中间池化若改成 4 个读口并行（1 拍/像素）可省 ~96,000 拍 → ~2.76 ms。

### 6.3 片上存储：当前版本 vs 带化版本

当前 RTL 为了**波形上看完整数据流**，六块平面都是**全平面**存：

| 缓冲 | 全平面（当前） | 带化 16 行（建议综合版） |
|------|----------------|--------------------------|
| LB0 320×240×3B | 230,400 B | 15,360 B |
| L1O 320×240×16B | 1,228,800 B | 20,480 B（只需给池化留 4 行） |
| LB1 160×120×16B | 307,200 B | 40,960 B |
| L2O 160×120×32B | 614,400 B | 20,480 B（同上 4 行） |
| LB2 80×60×32B | 153,600 B | 40,960 B |
| L3O 80×60×64B | 307,200 B | 0（直接流出去 DDR，块内 6.4 kB 暂存） |
| 输入行缓冲 4 行×640×3B | 1,920 B（2 行） | 7,680 B |
| **合计** | **≈2.71 MB ✗** | **≈153 kB ✓（进 160 kB）** |

带化要改两件事（`mb2_lb` 加 `DEPTH` 参数、行号取模；`mb2_top` 把"整级做完再池化"
改成**流水线调度**：某个 tile 行做完就把新增的 5 行池化给下一级，下一级
`ir` 行的窗口就绪条件是上一级已完成 tile 行 `2*ir+1`）：

```
band 深度 = 窗口 12 行 + 生产者领先 4 行 = 16 行（取 DEPTH=32 的 2 的幂取模，安全）
就绪条件: L1 行 r <= 输入池化已产生到 10r+10 行
          L2 行 r <= L1 已完成 tile 行 2r+1
          L3 行 r <= L2 已完成 tile 行 2r+1
```
这样每级只需保留"自己窗口那 12 行 + 生产者刚写出的几行"，**不需要重算，也不额外读 DDR**。

## 6.4 【WIP】带化流水线版（做过一轮，未完成，已回退）

当前交付的是**全平面版**（6.3 左列，2.71 MB）。带化版做了一轮，架构和参数如下，
代码已回退（`git checkout cc23411 -- mb2/mb2_top.v mb2/mb2_tb.v`），下次可从这里接着做：

**架构收敛结果（比全平面版更省更快）**
- 把 2×2 max 池化**融进执行器的写回**：一个 tile 的 10×10 量化结果在片上直接池化成
  5×5 写进下一级的带 → **L1O/L2O/L3O 三块平面完全不需要**，两遍独立池化也省掉
  （640×480 上省 ~110k 拍）。
- 只留三块带：LB0(320×240×3)、LB1(160×120×16)、LB2(80×60×32)，`DEPTH=16`
  → 15.4 kB + 41.0 kB + 41.0 kB + 输入行缓冲 3.8 kB + 权重 4 kB ≈ **105 kB ✓ 进 160 kB**。
- `mb2_lb` 已支持 `DEPTH` 参数（行号取模），`DEPTH=0` 仍是全平面 → 对现有版本零影响 ✓（已保留）。

**波前调度（就绪 + 节流）**
```
needK  = min(10*nrK + 10, IHK-1)          // 平面临界必须截断！
needKr = needK/5 + 1                       // 上一级要完成多少个 tile 行
L3 行 r : nr1 >= need2r
L2 行 r : nr0 >= need1r  且 (r <= 2*nr2+2 或 L3 已完成)   // 节流: 别覆盖 L3 还要读的带
L1 行 r : prow > need0   且 (r <= 2*nr1+2 或 L2 已完成)
输入    : prow <= 10*nr0 + 12（L1 未做完时）
终止    : nr0>=T1R 且 nr1>=T2R 且 nr2>=T3R
```

## 8. 开发中踩到的坑（后人省时间）

1. **端口位宽不匹配 → Z**：6bit 的 `ir/ic` 直接连 10bit 端口，ModelSim 高位置 **Z**，
   一路 X 到输出。必须显式 `{4'd0, ir}` 补零。
2. **`COUT*CIN` 被截成 6bit**：`64*32 = 2048` 截断成 0，点卷积阶段一拍都没跑。
   改成显式 13bit `NPC`。
3. **反射索引**：`refl(rd_ir-1+R, N)` 里表达式混了无符号数会变成 `32'hFFFFFFFF`，
   越界读 X。改成显式 `$signed` 预计算 12 个行/列地址。
4. **`py[9:0]` 这种越界 part-select** 会给出 X → 写地址变 X，整块内存写不进去。
5. **窗口读地址要传 tile 在**原面上的坐标** `10*ir`，不是 tile 序号**（否则只有 tile(0,0) 对）。
6. **复用模式第一个通道的抽头会晚一拍**（装载沿位置不同），必须对齐（见 2.1）。
7. **`op` 从 0 跳到 1** 会让 PE 内部 `op_reg[2]` 晚 2 拍 → 用 `E_PRE` 预置。
9. **tile 行数/列数写反**：`T*R` 必须用"高/10"、`T*C` 用"宽/10"。方形图看不出来，
   640×480 会让 `c ≥ 240` 一大片根本没算（第一处 mismatch 正好在 c=240，很典型）。
10. 不要把中文注释文件交给 PowerShell `Get-Content|Set-Content` 往返，会变乱码；
   用编辑工具直接改。
